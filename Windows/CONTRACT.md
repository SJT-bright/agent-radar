# Shared Windows implementation contract

Version 1.9.1. .NET 10 native WPF, shared local Python adapters/bridge frozen using PyInstaller on Windows. User asks 1:1 feature and visual recreation of current Mac app, not merely a list viewer. Read Sources/*.swift for behavior. No placeholder or fake-success controls.

Contracts.cs belongs to primary integration; do not edit without recording exact required change. Backend provides:
- SettingsRepository(string directory): DataDirectory, Load():RadarSettings, Save(RadarSettings):void (atomic JSON, finite position encoding), WriteCareRegistry(RadarSettings):void.
- WorkerClient(string workerExe,string nativeHelperExe):IWorkerClient.
- RadarRuntime(SettingsRepository,IWorkerClient,IPlatformServices,Func<DateTimeOffset>? clock=null):IDisposable.
- Runtime properties Settings:RadarSettings, Sessions:IReadOnlyList<SessionRecord>, VisibleSessions:IReadOnlyList<SessionRecord>, Notices:IReadOnlyList<NoticeRecord>, QueueCount:int, Fresh:bool, Summary:string, Diagnostic:string.
- Runtime events Changed:Action?, NoticeRaised:Action<NoticeRecord>?. UI subscribes using Dispatcher.
- StartAsync(token), Tick(), UpdateSettings(Action<RadarSettings>), ToggleSupervision(SessionRecord), ToggleAppSupervision(string), ToggleCare(SessionRecord), Remove(SessionRecord), RestoreRemoved(), ManualResume(SessionRecord), StartCompletedSelected(), AcknowledgeNotice(string), InspectAsync(SessionRecord):Task<BridgeResult>, OpenAsync(SessionRecord):Task<NavigationResult>.
- Native namespace AgentRadar.Windows.Services, WindowsPlatform:IPlatformServices, NativeAutomation.Run(string requestJson):string. Bootstrap on --native-bridge reads bounded stdin, invokes NativeAutomation and emits ONE JSON object; never starts normal UI/worker or invokes other AI during tests.
- Native protocol stages snapshot (read only, return identity,busy,input_count,send_available,code), route, write(text exact <=2000 scalar, overwrite), send. Fields id/app_id/title/project/navigation_key/target/pid/source/started_at. Requests are bounded to 32 KiB; UI text remains limited to 2000 Unicode scalars. Every mutation must recheck stable metadata via supplied Python supervisor, current original window identity, hardware idle/user state. Never Enter fallback. Return attempted true once writing may have occurred. Only fixed metadata, no draft/chat values/credentials in output.
- Python worker arguments --watch or --bridge or --once or --record-operation. Shared JSON shapes in Contracts.cs. --bridge receives stdin <=8192 UTF8 JSON. UI sets AGENT_RADAR_NATIVE_HELPER to its own installed executable; this is NOT supplied by untrusted request. Native helper may not independently authorize any write.
- Settings at %APPDATA%/AgentRadar/settings.json; health.json and existing Journal/operation receipts only in app-owned directory. Registry selected-openclaw-sessions.json {version:1,ids:[stableIDs],care_ids:[explicitly selected IDs]}. continuous_authorized comes from this own-file registry, not external session DB. User-selected OpenClaw child stays manual_only unless care authorization exists; no cron/general child discovery.
- Application reminder scope: RadarSettings.AllReminderApps defaults true for legacy settings; ReminderAppIds is an independent persisted allowlist. Filter popup and sound using explicit NoticeRecord.AppId or RelatedAppIds (conflict eligible when any related app is selected). Filter saves remove current/pending cards immediately, consume old completion rounds, and preserve authorized FIFO work, supervision, care and send settings. Settings include a dedicated 提醒 tab with app checkboxes, search, 全选 and 全不选; apply on draft save.
- Per-session care means watch continuously, auto recover fresh verified interruptions with global auto send on, <=3 automatic recoveries per hour then show cooldown and continue observing (no same-round replay); stop/wait/unknown never sends. Use same FIFO desktop channel and actual same-session new-round confirmation.
- Config openclaw-local-gateway.json {url:"ws://127.0.0.1:18789"}, only loopback ws URLs. platform-config.json {openclaw_home:"...",wsl_distribution:"...",wsl_executable:"/usr/local/bin/openclaw"}. Native paths and explicitly chosen local WSL UNC paths only; no external UNC shares. CLI handles auth; do not read credentials. Changing rules/scope/pause/auto send cancels old queued/executing commands.

UI parity: dark translucent frosted fixed narrow panel 238 logical points expanded (max ~548 height), compact 60x32, right control with 30-point zones, always on top, hover expand/collapse/menu (80/180ms), saved top-right anchor and real header drag, per-app groups and folder-primary/title-secondary rows, timers/status colors, conflict warning, history/removed entries, context menus. Settings tabs 运行/提醒/监督/提示词/限流 with search/collapse, draft save/restore and close protection, >2000 full text retained/error not truncated. Prompts show effective text/source. Reminder queue dedup per session, recovering countdown/status, open actual conversation only dismisses on success, acknowledge one/all, sound/popup independent. Runtime/menu includes startup, keep awake, diagnostics, readonly input checks, tray show/exit; never expose code implementation in ordinary flow.

Tests: Core.Tests is a console semantic suite targeting net10.0 with fake clock/worker/platform and isolated data. Windows UI --smoke-test OUTPUT_DIR must actually create product windows, exercise expand/collapse, settings tabs/draft save/load, reminders and row controls, emit JSON results and screenshots, then exit. No real session data/sends/credentials. Primary writes smoke harness, CI, installer and package scripts. UI can provide internal accessibility names plus public methods for direct product control invocation. Do not claim external app sends verified in CI.
