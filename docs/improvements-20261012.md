# 1.8.25：本地 OpenClaw 恢复与监控改进

2026-10-12，build79，macOS 13+ / Apple Silicon。

本版加入独立本地 OpenClaw 数据源和原会话恢复通道，修正诊断窗口阻塞实时更新的问题，并完成五个并行改进方向。桌面发送继续严格按入队顺序执行；未知、主动停止、等待确认和身份冲突均不发送。

## 改动及使用方法

| 方向 | 最终行为 | 用户可检查的入口 |
| --- | --- | --- |
| 会话显示 | 历史限额先排除已显示软件，避免被同软件记录占满；主动停止使用中性状态；空列表解释暂停、过滤、权限或读取问题 | 浮窗和后台读取情况 |
| 操作回执 | 每次操作共享一个 ID，记录排队、核验、发送、确认和超时；只有结构元数据，身份以 SHA-256 保存 | 查询 AI 监督状态 → 最近操作回执 |
| 生命周期 | 可选 Claude Code hook 用 session_id / prompt_id 关联开始、正常结束、失败与权限等待；冲突或缺少轮次不猜测 | 可审查的 record_claude_event.py --print-config |
| 窗口刷新 | 结构通知合并后局部重扫；每三秒保留完整扫描；退出、权限变化、睡眠和不支持通知时回退 | health.json 的完整/局部扫描及观察应用计数 |
| 输入兼容与提示词 | 原会话只读检查分别报告窗口、身份、输入框、发送按钮；软件版本及未知兼容性可见；显示实际采用的提示词与来源 | 会话右键 → 只读检查原会话输入区；设置 → 提示词/监督 |
| 实时性补修 | 只读诊断使用非阻塞窗口，避免弹窗打开时采集回调积压、活动状态过期 | 打开诊断时观察 health.json 的 local_update |

提醒的“打开原会话”须等实际导航回调确认打开对话才能关闭卡片。只打开应用/工作区、忙碌或跳转失败会保留提醒。所有异步结果仍核对当前卡片，不会误清另一条提醒。

## 本地 OpenClaw

读取 ~/.openclaw/agents/*/agent/openclaw-agent.sqlite 的固定会话元数据和生命周期字段，SQLite 使用 mode=ro 和 query_only，不读取认证表、模型配置或消息正文。单个数据库查询设两秒预算，每个代理最多 40 条会话、最多 8 个代理、每个目标最多 512 条生命周期事件。精确会话查询在限额前筛选；同一会话的映射歧义、归档、轮次冲突、未来时间和过期运行标记保留待确认。

本轮实测确认运行事件的 seq 会重置，run ID 也可能被同会话多个执行段复用。因此按 created_at、seq 排序，以同一 run 最新执行段的开始和结束计算状态；不以修改时间推断运行。读取有界本地 gateway.log 时只保留对应 run 的固定错误分类，不保留原始日志、请求正文或原始错误。

恢复通过已有 OpenClaw CLI 的本地 Gateway chat.send RPC，固定核验 ws://127.0.0.1:19189，并核对原 session ID、sessionKey、最新执行段和生命周期修订。使用确定的幂等键，deliver=false，不停止其他任务。离线时在写入前有限次保持队首重试；请求已经发出后即使超时也不重发。同一原会话、预期 run ID 和晚于实际发送的新执行段三者一致，才能确认恢复并让下一项继续。

普通主会话接入现有监督设置。subagent、cron 等后台会话不自动发现；用户明确选中的后台会话可保留在雷达自己的 selected-openclaw-sessions.json，仅用于显示及手动恢复。按软件监督和“启动历史完成会话”不会自动启动这类目标。恢复不改全局开关、不重启 OpenClaw、不操作其屏幕输入框，也不向外部频道交付消息。

使用：展开 OpenClaw 分组 → 右键目标 → “只读检查原会话输入区…”核验；明确中断后可选“手动恢复此会话”。目标已运行、主动停止、等待确认、认证需人工处理或身份无法核验时会拒绝发送。端口目前对应本轮验证的本地实例，其他安装需要适配，不能宣称支持任意 OpenClaw 配置。

## 实际验证与边界

完整回归通过 410 项 Python 及全部 Swift 检查；补充异常可选字段隔离后 Python 全量为 411 项。覆盖 28 项 FIFO、5102 项监督模拟、116 项提示词草稿、118 项窗口观察器及 37 项硬件输入检查。生产组件、正式安装版 UI 和真实恢复分别核验，模拟发送不等于实际交付。

用户指定的原 OpenClaw 会话确实完成一次恢复：只发一条已授权恢复文字，原会话返回预期 run ID，新执行段在发送后约 2.48 秒进入 running。随后该 run 再次出现 Connection error 并中断，雷达显示“网络连接失败或断开”。这个结果证明原会话定位、单次请求与新轮确认有效；不能证明底层模型连接已经稳定，也不能把这次单次脚本通道验收称为安装版所有自动恢复场景均通过。

安装版为既有 AgentRadar Local 签名，322 个包内文件与候选一致。实际浮窗显示 OpenClaw 原目标和错误原因，右键只读检查返回原会话 ID/键已核验及本地 RPC 说明；窗口读取、输入组件分别查询通过。监督、提示词、自动发送、防重复记录及已选择的 OpenClaw 目标保留。

## 五个 Grok 进程

按用户要求使用本机已登录 Grok CLI，五个独立源码副本并行运行，指定 grok-4.7-build-fast。显示、回执、输入契约及提示词三个任务完成并返回结果；生命周期、窗口通知两个任务因 CLI hook 多次超时达到任务时限。后两项的候选由主 Agent 接管、审查、补齐与测试，不称为五项均由 Grok 独立完成。所有候选最终由主线集成；子进程不安装应用、不改正式数据或代发真实消息。

## 后续最有价值的工作

1. **定位 OpenClaw 连接错误。** 当前可确认的是原会话新轮次恢复成功后再次连接失败，Gateway 健康不等于模型调用健康。下一步应把对应 run 的阶段、固定错误码、模型入口连通性与代理可达性串联，先定位再调整配置。认证、代理和模型配置本轮保持原样；不能凭 LaunchAgent 缺少某个环境键就认定根因。
2. **扩大控件契约样本。** 当前 Codex 版本已有真实占位结构样本，其他应用升级后的版本多为未知。按版本保存匿名结构签名与真实只读回执，再补 UI 回归；未知不能获得发送权限。系统辅助功能权限仍须安装后实查。
3. **验证通知收益。** 已有生命周期和资源回退检查及实机完整/局部扫描计数；尚未做多应用长时间 CPU、通知漏报率与 P95 延迟对比。保留完整扫描兜底，在量化结果支持后再调频率。
4. **逐步使用官方生命周期来源。** 可选 hook 不会自动安装；当前 Claude 仍有本地日志回退。应在用户选定的软件上接入官方事件、明确权限等待和主动停止，保持原始数据与雷达状态分离。

对标采用官方事件、请求 ID/幂等与结构通知机制：[OpenClaw Gateway](https://docs.openclaw.ai/gateway/protocol)、[Claude Code hooks](https://code.claude.com/docs/en/hooks)、[Apple AXObserver](https://developer.apple.com/documentation/applicationservices/axobserver)。此前六个官方对标及具体建议见 [全项目审查](audit-20261011.md)。
