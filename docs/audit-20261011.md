# 2026-10-11 全项目审查与优化

范围：三个独立子任务分别检查采集与使用体验、发送与顺序队列、六个官方对标；主线核对复现并实施。此次是有针对性的代码和体验审查，不能据此保证项目没有其他漏洞。

## 最有价值的优化：Codex 按目标核验长日志

旧发送桥每次启动都是冷缓存，只采集第一块日志。超过 8 MiB 的本轮记录需要后台多次回溯；后台已识别为结束，短进程却仍判未知。旧桥返回 `state_changed` 后，该轮已被策略认领，不再排队，形成漏恢复。

1.8.23 改为精确查询目标 ID，不受近期 50 条限制；只回溯这一条日志，每块仍不超过 8 MiB，只缓存最多 4096 条结构元数据。每次回溯重新查询数据库，最多 16 次读取，读取完成后检查 2 秒预热预算。单次系统 I/O 可能超过预算，桥仍有原有 40 秒外层超时。

仍在回溯且无法核验时返回 `state_unverified`，未写入请求最多三次原位重试。真的换轮、归档、主动停止、等待确认、身份变化仍拒绝；数据库失效不能使用旧采集快照放行。输入后仍逐次重新核验并回读，不重发已尝试轮次。

实际只读样本的目标日志为 967,716,745 字节。旧版第一次全量采集缓存 50 条日志，818 毫秒后返回未知且无本轮起点；新版缓存一条，195 毫秒内核验为运行中。这个单次测量证明该真实样本可读，不能当作所有设备的性能承诺；没有切换窗口、写入或发送。

## 本次同时修复

- **跳转失败和同名误定位**：检查系统 URL 打开结果。当前窗口或网页区域若导出不同 thread URL，即使标题相同也拒绝。未导出 ID 时，用全库主任务标题核对唯一性，包含归档和近期 50 条之外的记录；归一化和截断后的重名也拒绝，超过 2048 条的标题核验预算同样拒绝。侧栏链接不能证明当前对话。
- **发送确认过早**：桥返回实际开始发送的时刻。Codex 新轮必须在这一时刻之后，不能用延迟曝光的发送前轮次释放 FIFO；回调返回前已经开始的快速新轮仍可确认。只有整秒时间的其他适配器保留整秒精度，不能据此承诺亚秒级因果判断。
- **自动恢复专属提示词未生效**：自动策略的普通观察和 ZCode 短轮兜底都传入按软件恢复提示词及通用恢复提示词，与手动路径一致。
- **清空专属提示词无法保存**：删除已存非空值会标记未保存修改，保存后仅删除对应覆盖项；新增空白键不产生假修改，其他应用的设置继续保留。

## 官方对标与详细建议

以下排序是本项目的工程判断。

1. **优先把界面兼容性变成可检查的契约。** 参考 [Power Automate selector 测试](https://learn.microsoft.com/en-us/power-automate/desktop-flows/test-selectors) 对唯一命中、缺失和歧义的区分，为每款软件保存版本范围、已验证主输入区结构和读取预算。向用户说明失败的是窗口、会话身份、输入框还是发送控件；歧义继续拒发。收益是软件更新后能快速定位失效层。成本中等；验收要覆盖空框、草稿、异步加载、同名会话和多个输入区。
2. **建立按操作保留的回执和直达诊断。** 参考 [SwiftBar 的错误呈现](https://github.com/swiftbar/SwiftBar/blob/main/README.md)，概览只给简短状态，详情说明原因。当前最新回执会被下一软件覆盖，难以追溯；建议按操作 ID 保留入队、身份核验、回读、发送、新轮确认与取消，并限制数量、只存元数据。空列表直接显示权限/数据源/当天过滤等实际原因及检查入口。成本低到中等；验收要求每个“已确认”可追到原会话新轮，超时、取消和拒绝都能解释。
3. **试点最小生命周期事件入口。** [Claude Code hooks](https://code.claude.com/docs/en/hooks) 区分用户提交、正常停止、失败和等待权限。只接收会话 ID、轮次 ID、事件、时间和工作区，丢弃正文与工具参数；原有只读采集继续兜底。可减少旧 busy 描述符与新结束事件冲突。成本中等；重复事件、旧轮晚到、主动停止和权限等待都必须单独验证。
4. **用 AX 通知唤醒局部重扫。** [Apple AXObserver](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate) 与 [Hammerspoon observer](https://www.hammerspoon.org/docs/hs.axuielement.observer.html) 可借鉴观察者生命周期。回调只令局部缓存失效，合并扫描；保留轮询，处理不支持通知、PID 复用、窗口重建和休眠唤醒。收益是减少重复遍历及加载等待。成本中等偏高；先在单软件比较扫描次数、CPU 和确认延迟，通知缺失不能停止更新。
5. **统一“当前生效提示词”展示。** Grok 空专属续接字段实际使用专用默认，与页面“使用通用”的说明不一致。先统一现有产品语义和说明，再直接展示下一次采用的文字及来源。成本低；验收要覆盖专属、通用、专用默认、恢复和限流文字，不能为了改说明静默改变用户已授权内容。
6. **为官方协议保留能力入口。** [Codex App Server](https://learn.chatgpt.com/docs/app-server) 提供结构化轮次事件，但 `thread/read` 不加载或订阅线程。新开服务不能证明原桌面线程状态，也不能为监控自动恢复历史。先在隔离环境核实原服务是否提供可用只读订阅，再考虑接入。成本高，当前没有完成可行性验收。

## 剩余问题与验证边界

- 桌面通道忙时，“打开原对话”底层未打开，提醒外层仍当作成功并关闭；这是确定的回调问题，下一步应返回真实结果，忙时保留提醒。
- 主动停止条目被排序置顶，与中性展示约定不同；当前软件当天历史还可能被未展示软件的记录占满全局 12 条名额。这两项已合成复现，尚未修改。
- Claude 旧 busy 描述符覆盖更新结束事件已合成复现，真实发生频率及描述符更新契约尚未核实，不能直接套任意超时。
- Qoder 空工作目录会导致整帧解码失败的机制已复现，但真实两版 schema 均为 `NOT NULL`；它是外部格式损坏/变更的防御建议，不能称为当前正常数据 Bug。
- Codex 未导出稳定可见 ID 时仍依赖系统跳转成功、全库标题唯一及主输入区核验。未来若布局或索引失效，继续拒绝；不能宣称所有布局都可操作。
- 超出预热或标题检查预算仍待确认；三次原位重试失败后明确终止，不无限扫描、不重复发送。

265 项基线 Python 测试之外新增 30 项冷读及身份边界检查，顺序队列增至 22 项，提示词草稿增至 92 项。完整回归、正式安装与桌面复查结果另见发布验证。

本次独立观察到 1.8.22 一次已授权 Codex 自动发送：持久记录绑定同会话同旧轮次，发送回执后 0.572 秒出现该会话新轮，健康记录随后显示发送已确认。它是另一条 Codex 会话，不能证明最初用户截图目标已发送，也不能自动算作后续版本的真实发送验收。
